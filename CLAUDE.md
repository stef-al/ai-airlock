# AI Airlock: working notes

Offline, browser-only masking of secrets/PII before pasting into AI chatbots, and restoring them in the reply.
Deliverables: `dist/airlock.html` (text; Vite + vite-plugin-singlefile, strict hash-based CSP, inline Web Worker) and `dist/airlock-media.html` (`vite build --mode media`: adds images and documents; Tesseract OCR, pdf.js and BlazeFace run as WebAssembly/TF.js from assets embedded as inert base64 data blocks; its CSP adds only `'wasm-unsafe-eval'`). Images (phase A), PDF (phase B), Office files (phase C) and faces (phase D) are done.

## Commands
- `npm test`: vitest (unit tests + corpus: structure guard OK and mask→restore byte-identical on every fixture, with and without the file name; `tests/sniff.test.ts` = format detection of pasted snippets)
- `npm run metrics [-- --details --set=dev|holdout --strict --sniff]`: precision/recall per category/detector/type on `tests/corpus` (`--sniff` ignores file names, as for pasted text)
- `npm run metrics:media [-- --quick --style=clean --details --strict]` (needs the build): the corpus rendered as screenshots in 5 styles, run through `airlock-media.html#selftest`; recall = labelled span ≥ 98% covered, leak = labelled value still readable by OCR in the redacted copy. `-- --pdf` instead prints the corpus to PDFs (text PDF in Arial and monospace, several pages; scanned PDF = a screenshot as the page): recall = every occurrence of a labelled value ≥ 98% inside findings in the document text, leak = readable by OCR in the copy's pages
- `npm run metrics:office [-- --details --kind=docx,pptx,xlsx --soffice]`: Node only; every fixture written as DOCX (runs split), PPTX (10 lines per slide) and XLSX (CSV as a sheet, else one line per cell) through `media/office`; recall = every occurrence ≥ 98% inside findings, leak = value left anywhere in the copy's XML, broken = XML not well formed; `--soffice` converts every copy with LibreOffice
- `npm run metrics:faces [-- --quick --details --min-tile=N --max-tiles=N --min-score=X]` (needs the build): downloads the test photos once into `$TMPDIR/airlock-faces-data` (npm `@vladmandic/face-api` samples, PyPI scikit-image `astronaut.png`; hashes and hand-marked boxes in `tests/faces/sources.json`, never the photos), then recall on group photos and composites at known face heights, false boxes on text screenshots, an end-to-end check through the image pipeline; the knobs override the detector defaults for tuning
- `npm run build`: typecheck, both bundles, then `scripts/check-dist.mjs` (single files, CSP, data blocks, size budgets; network primitives: whole-file scan for the text file, module-level scan of our own code in `vite.config.ts` for both, vendor libraries excluded)
- `npm run smoke`: real Chromium opens both files from file:// (needs `npm run build` first); `smoke-media.mjs` checks the face detector runs on its WebAssembly backend and drives images, text/scanned/password PDFs (image-only copies checked with `pdfInfo` and OCR), a DOCX with a picture (copy checked by unzipping, OCR and LibreOffice when installed) and restore with zero requests and zero CSP violations
- `npm run dev` / `npm run dev:media`: dev servers (no CSP; media assets are served from node_modules)

Word lists that keep them quiet on ordinary words: `data/words.ts`.
- `data/names.generated.ts` is generated by `scripts/gen-names.ts` from @faker-js/faker (gitignored; npm `pre*` hooks and `tests/global-setup.ts` create it).
- `Settings.options` holds Tier 2 knobs: `ipPrivate`, `ipLocalhost`, `hostSuffixes`, `companyDomains`, `idPacksOff` (read with `opt()` from `settings.ts`).

## Architecture (`src/`)
- `engine/` pure TS, no DOM, runs in Node. Pipeline: `segment → detect → resolve → placeholders → guard`.
  - `segment/`: turn text into a `Doc`: segments that tile the text with a scope (prose, comment, string, config, identifier, key, structure) plus key/value `pairs` and table `columns` (a two-column Markdown table also gives one pair per row: forms). Tables read from Office files and PDFs come under a header of column letters (`segment/tables.ts`: `letters`, `headerLike`): `markdown.ts` then lets a header-like first row name the columns while its cells stay prose (maskable), so a form's first row is not protected as a key. json (jsonc-parser), yaml (yaml), xml/csv/env/ini/markdown (own offset-aware scanners), code lexer for js/ts/python/java/csharp/go/php/sql/bash/powershell (`code.ts`), `index.ts` sniffs the format (config scoring on non-comment lines, then language signals + code-shaped line ratio before markdown; a sniffed YAML/JSON/XML that does not parse falls back to prose).
  - `detectors/*`: each exports a `Detector`. `cues.ts` = secret-name analysis (multilingual cue words, qualifiers, value verdicts). `secrets-context.ts` also takes a word right after a non-weak cue without a connector when `strongSecretShape` says it can only be a secret. `custom.ts` columns: a column whose values are mostly field names (a form's left side) is never classified.
  - `resolve.ts`: scope filter, allowlist, confidence floor, overlap resolution (priority 4 user lists > 3 known/validated formats > 2 context > 1 heuristics; a longer hit containing lower ones wins).
  - `placeholders.ts`: `Mapping` (memory only, identity = exact original string) and context-safe rendering. `mask.ts` applies it, `guard.ts` re-segments the output and compares the skeleton; the first difference locates the culprit, which gets a safer placeholder or is skipped and flagged (3 s budget; past it, replacements are kept and the guard reports failure).
  - `restore.ts`: tolerant restore + report. `settings.ts`: defaults, presets, profile (de)serialisation.
- `worker/`: thin wrapper (`engine.worker.ts`, imported with `?worker&inline`). Cancel = terminate and respawn (`ui/engineClient.ts`); jobs run one at a time and a mask job hands the session mapping to the next one through `onResult` (synchronously, before the next job is built). In `ui/App.tsx` every document change goes through `updateDocs` so `docsRef` is current before React re-renders. Settings from localStorage and imported profiles pass `sanitizeSettings`.
- `ui/`: React. Imports only `engine/light.ts` (no detectors) so the main bundle stays small. No inline styles (CSP).
- `media/` (media build only; the UI reaches it through `ui/media.ts`, whose dynamic import is statically dead in the text build): `assetList.ts` (what gets embedded), `assets.ts` (reads data blocks), `media.worker.ts` + `mediaClient.ts` (Tesseract from bytes, QR codes with jsQR, painting redactions on OffscreenCanvas), `ocrfix.ts` (pure, runs in the worker on the decoded pixels: underscores OCR dropped = ink below the local baseline across a gap and none in the body, not under the letters (underlines), not reaching the next line's top, only between words that can form an identifier (not after punctuation, not two capitalised words, not before a date or URL); monospace words split around narrow glyphs (gap < 0.45 pitch, pitch from letter pairs, only when most lines are monospace); `indent` of monospace lines), `ocrdoc.ts` (pure: OCR words → text with one box per UTF-16 unit, indentation, quote repair, wrapped tokens, `spanBoxes`, `findValue`), `metadata.ts` (pure: EXIF/XMP/PNG text/frames report), `image.ts` (orchestration: read → engine analyze/mask jobs → boxes labelled with placeholders → render → re-OCR verify that covers every place a masked value is still readable), `options.ts` (pure image and PDF options), `paint.ts` (opaque labelled boxes, shared by the worker and the page), `selftest.ts` (`#selftest` hook for the scripts: `processImage`, `processPdf`, `pdfInfo`, `readText`, `faces`).
- Faces: `facedetect.ts` (pure: BlazeFace back-model anchors, `decode`, `tilePlan` = whole image + finest tiles of about 200 px (larger for big images, ≤ ~80) + tiles three times as large, `merge` = union of a cluster, `expand` for hair and ears), `faces.ts` (in the media worker: TF.js WebAssembly backend from embedded bytes through a wrapped `tf.env().platform.fetch`, threads off, CPU fallback; flat tiles skipped; `MIN_SCORE` 0.7 from the metric). Faces are regions (`ocrdoc.ts` `faceRegion`: type FACE, `swallow: false` so OCR words under a box stay in the text; a unique text so two faces never share a placeholder) and become FACE hits like QR codes (`image.ts` `regionHits`; PDF pages that get OCR in `pdfdoc.ts`/`pdftext.ts`); `imgFaces` option, part of `readKey`.
- PDF: `pdf.ts` (pdf.js legacy build with an inline worker, fonts/wasm from data blocks via `BinaryDataFactory`, `useSystemFonts: false` so a non-embedded font never becomes a `url()` font that `font-src 'none'` refuses; open with password, inventory of what the copy drops, text items + annotations + whether the page paints images, render with annotation appearances), `pdftext.ts` (pure: items placed by `Util.transform(viewport, item)` with any rotation, characters spread by measured widths, lines, monospace indentation, tables (cells split where a line jumps by a font height, pdf.js's wide whitespace items; consecutive rows sharing two cell edges, one column of short cells; written as Markdown under a letters header; a bullet or number in the first cell is a list, not a table; never soft-wrap joined), soft-wrap joins for text printed with wrapping (never before a capitalised word; digits alone only with a column edge), `cont`, OCR words the text layer lacks, annotation/QR lines; boxes in page points), `pdfwrite.ts` (pure: image-only PDF, one DCT image per page, nothing else), `pdfdoc.ts` (orchestration: OCR pages that show images or have no text layer, one joined text with `=== Page N ===` markers, render at 100/150/200 DPI → paint → re-OCR verify per page → `writeImagePdf`; open documents cached by bytes, `closePdf` on remove/forget, `cancelPdf`). Never fetch anything: `connect-src 'none'` also applies inside workers.
- Image documents (`DocState.kind === 'image'`) reuse the text flow: their `text` is the OCR text, analysed with `ocr: true` (format sniffed tolerantly plus a prose reading, checksummed shapes near cues accepted, entropy needs a cue) and masked as prose; QR contents are `extra` region hits. `ui/ImageReview.tsx` and `ui/PdfReview.tsx` draw on canvas through `ui/PageView.tsx` (no inline styles).
- Office (`media/office/`, pure, Node-testable): `xml.ts` (offset-aware tag scanner, attributes with value offsets, `decodeMap`, `splice`), `package.ts` (`Pkg`: parts, content types, relationships, `removePart`/`renamePart`, `clone`, deterministic ZIP; refuses more than 200 MB per part or 600 MB in all from the ZIP directory before inflating, names OpenDocument files), `scrub.ts` (accept tracked changes, rename authors, empty properties, remove thumbnail/custom properties/macros/printer settings, blank EMF/WMF/OLE; runs before the text is read: offsets change), `text.ts` (`TextBuilder`: runs = part + raw offsets + position in the text; WordprocessingML and DrawingML paragraphs, tables as Markdown under a letters header (width from the first row), field codes and `w:fldSimple`, alt text (DrawingML, VML), links and tooltips, custom XML), `text-pptx.ts` (also `ppt/tags`), `text-xlsx.ts` (sheets as Markdown tables under a letters header; values cached from linked workbooks; shared strings, inline strings, formula results with `drop` of the formula, number/date cells with `shown` + `cell` rewritten as text cells), `office.ts` (`openOffice` incl. embedded Office files one level deep and the media list, `runEdits`: placeholder into the first run a finding touches, union of edits for runs at one place, `buildCopy` requires a redacted copy of every picture; `officeAnalyzeOptions`: DOCX/PPTX sniffed, XLSX as Markdown). `media/officedoc.ts` adds the browser part (decodable pictures, SVG rasterised through a `data:` image, blanks, `officeCopy`: pictures whose child document was removed become blanks).
- Office documents (`kind === 'office'`, `DocState.office`): the text review of a text document (no editing) plus `ui/OfficeReview.tsx`; pictures are child image documents (`parent.key` = media path) whose `image.out` (reviewed) goes into the copy on Download.
- PDF documents (`kind === 'pdf'`, `DocState.pdf`) work the same way: `text` is the joined page text, analysed with `ocr: true` only when OCR added words to some page, masked as prose; boxes are in page points (`PdfState.pages[i].text`, `offsets[i]` = where page i starts in `text`); manual boxes carry their page.
- `tests/corpus/*.fixture`: labelled inputs. `⟦TYPE:text⟧` marks expected spans, `{{aws:1}}` style macros expand to test-time generated tokens (`tests/tokens.ts`) so no realistic secret is ever committed. `#! set: holdout` fixtures were written before tuning.

## Detector interface (`engine/types.ts`)
```ts
interface Detector { id; label; category; types: string[]; defaultScopes: Scope[];
  detect(doc: Doc, cfg: DetectorConfig, ctx: RunCtx): Hit[] }   // pure, linear time
interface Hit { start; end; detector; type; category; confidence; reason; priority }
```
Add a detector: write it in `engine/detectors/`, add it to `BASE_DETECTORS` (engine/index.ts) and to `DETECTOR_META` (engine/meta.ts; a test keeps both in sync), add fixtures. Hits are filtered to the detector's enabled scopes by `resolve.ts`, so detectors never need to care about structure.

## Rules of the road
- Never change structure: keys, tags, identifiers, CSV headers stay out of reach unless the user enables the `identifier`/`key` scope; placeholders must be valid where they land (`hostOf` + `candidatesFor`).
- Regexes must be linear (bounded quantifiers, lookbehind anchors); `tests/engine.test.ts` throws hostile input at every detector.
- Never commit realistic secrets in tests; use macros. Never commit photos of people: `metrics:faces` downloads its test photos at run time (hashes and boxes only in `tests/faces/sources.json`).
- The media file never fetches: every engine, model and language file is an embedded data block, and libraries that want to fetch get their bytes from memory (`BinaryDataFactory` for pdf.js, `platform.fetch` for TF.js, `wasmBinary` for Tesseract).
