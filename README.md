# AI Airlock

Mask sensitive data in text, code, config files and logs **before** you paste them into an AI chatbot, entirely offline. Paste the AI's reply back and the real values are put in again.

**Flow:** paste or drop files → detection → review highlights → *Copy masked* … later: paste the reply → *Restore* → *Copy restored*.

Open `dist/airlock.html` (build it with `npm run build`, or use the GitHub Pages site). It is one self-contained file and works from disk, a shared drive or Pages. `dist/airlock-media.html` is the same app plus **images, PDF, Word, PowerPoint and Excel files** (about 27 MB: it carries an OCR engine, its language data and a PDF reader).

## What it detects
| Category | Examples |
|---|---|
| **Secrets** | Known formats: AWS/Azure/GCP/GitHub/GitLab/Slack/Stripe/npm/AI-provider keys (about 55 formats), JWTs, PEM/OpenSSH/PuTTY/PGP private keys, password hashes (bcrypt, argon2, crypt, PBKDF2…), connection strings and `user:pass@` URLs, Authorization headers, session cookies, secret URL parameters, credential files (`.npmrc`, `.netrc`, `.pgpass`, Docker config, Kubernetes Secrets…). By context: a literal next to a secret-like name (`password`, `token`, `api_key`, `Passwort`, `mot de passe`, `contraseña`, `hasło`, `heslo`…) in JSON, YAML, XML, .env, INI, properties, code (assignments, object literals, call arguments, SQL `IDENTIFIED BY`, PowerShell `ConvertTo-SecureString`, CLI flags) and prose. Unknown formats: entropy plus password shapes (`Summer2024!`) in Aggressive, boosted by cues in Balanced. |
| **Personal** | Emails; phone numbers (libphonenumber, region from the browser locale); person names (greetings, signatures, titles, mail headers, labels, `john.smith@…` → John Smith, name lists generated from faker locale data); organizations with legal suffixes (Ltd, Inc, GmbH, AG, S.A., B.V., s.r.o., a.s., Sp. z o.o. …); user names in paths (`/home/jsmith`, `C:\Users\jsmith`); dates of birth next to a birth cue; national IDs with checksums: US SSN, UK NI number, Czech/Slovak birth number, Polish PESEL. |
| **Financial** | IBAN (mod-97), payment cards (Luhn, brand and length), CVV and expiry next to a card. |
| **Network** | IPv4/IPv6 (private ranges and localhost toggleable), MAC addresses, hostnames under configurable internal suffixes and company domains. |
| **Custom** | Always-mask lists (clients, projects, products, employees; import from CSV/TXT, case-insensitive), your own regex rules with a live test box, and whole table columns classified by header and values (CSV and Markdown tables). |

### Images (airlock-media.html)
Drop or paste (Ctrl+V) screenshots and photos (PNG, JPEG, GIF, WebP, BMP); images embedded in pasted text (`data:` URIs in Markdown, HTML, JSON) are picked up too.
- **Text in the image** is read by OCR (Tesseract; English, German, French, Spanish, Italian, Polish, Czech; Settings → Images) and goes through the same detection as text, tuned for OCR: the format is still recognised, a plain-text reading runs alongside, quotes OCR got wrong are repaired, a token wrapped at the right edge is followed onto the next line, card/IBAN/ID shapes next to a cue count even when one misread digit breaks the checksum.
- **QR codes** are found, decoded and always covered; their content (2FA secrets, Wi-Fi passwords, links) is listed and can be restored like any value. **Passport and ID machine-readable zones** (MRZ) are found by their check digits.
- **The redacted copy is a new file:** opaque boxes on the decoded pixels (never blur), each labelled with its placeholder so the chatbot can refer to it and *Restore* works on its reply, no metadata (EXIF GPS location, camera, author, XMP, PNG text), the first frame of an animation. The copy is then **read again by OCR**: wherever a masked value is still readable (a second mention nobody flagged, a glyph sticking out) it is covered too, and what is left is reported.
- **You review every image** before copying it: correct values the OCR misread (the corrected value is what restore puts back) and drag to cover anything else. Faces, signatures, handwriting and logos are not found automatically yet.

### PDF files (airlock-media.html)
Drop a PDF: digital, scanned or both. A password-protected file asks for its password (kept in memory only; the copy has none).
- **Every page is read:** the text layer exactly, OCR on pages that show images or have no text layer (scans, screenshots inside a report, text drawn as shapes), form field values, comments and link targets. Lines that were printed with wrapping and broken inside a token (logs, CSV rows, long keys, emails) are joined again; monospace listings keep their indentation. All pages form one text with `=== Page N ===` markers: one detection, one placeholder mapping, the same review as for text.
- **The redacted copy is rebuilt from images of the pages:** each page is rendered as a viewer shows it (form values included), opaque boxes labelled with their placeholders are painted over the pixels, and a new PDF is written with one image per page and nothing else. Hidden and invisible text, hidden layers, earlier versions kept in the file, metadata (title, author, XMP), form fields, comments, links, bookmarks, attachments and scripts cannot survive; the report lists what was left out. Each page is then **read again by OCR** and any masked value still readable is covered too.
- **The masked text** of all pages is what you paste into the chatbot (*Copy text*); *Restore* works on the reply as for text. Settings → Images and PDF: resolution of the copy (100, 150 or 200 DPI), OCR on every page, page limit (100 by default).

### Word, PowerPoint and Excel files (airlock-media.html)
Drop a .docx, .pptx or .xlsx (macro-enabled files and templates too).
- **Everything that holds text is read:** body, tables, headers and footers, footnotes, comments, text boxes, speaker notes, slide footers, charts and SmartArt, cells (shared strings, numbers and dates, formula results), sheet headers and footers, pivot table caches, data connections, field codes, alt text, link targets, document variables and custom XML. Tables, and every sheet, become Markdown tables, so columns are classified by their header. A value split across formatting runs is found and replaced as a whole.
- **The copy keeps the file's layout:** each masked value is replaced in place by its placeholder (a number or date cell becomes a text cell; a formula whose result is masked keeps only the masked result). Pictures go through the image pipeline as documents of their own (OCR, QR codes, your review) and their redacted copies replace them, cropped-away areas included. Embedded Office files (a chart's workbook) are masked the same way.
- **What else the file carries is removed:** document and custom properties (author, company, title…), the thumbnail of the first page, macros, printer settings. Tracked changes are accepted (deleted text is gone); authors of comments and changes become Author 1, Author 2… Pictures a browser cannot decode (EMF, WMF, TIFF), embedded OLE objects and ActiveX controls are replaced by blanks. The report lists all of it, and the copy can be downloaded once every picture is redacted and reviewed.

Structure is never changed: keys, tags, identifiers, CSV headers, operators and Markdown syntax are protected (`getPassword()`, `PASSWORD_MIN_LENGTH` and `password_hash` are not secrets). Placeholders are valid where they land: `[PASSWORD_1]` in prose and strings, `PASSWORD_1` in unquoted YAML/env/URLs, numbers stay numbers, emails become `user1@example.com`, IPs become `192.0.2.x` / `2001:db8::n`, hosts become `srvN.example.net`, identifiers become `Client1Service`. Format-preserving fakes randomise letters and digits but keep every other character, so they stay valid in URLs and shell words; redacting a JSON/YAML number gives `0`. After masking the output is re-parsed and compared with the original; a replacement that would break structure gets a safer placeholder or is skipped and flagged for review. If that check runs out of time (3 s), the remaining replacements are kept and the guard reports FAILED: an unmasked secret is worse than a broken bracket. Masked JSON and YAML are also checked against the real parsers in development (same shape and value types, every placeholder style).

## What it cannot do (honest limits)
- It is rule-based. A secret with **no cue and no known format** (“log in with admin and hunter2”) is only caught by the Aggressive shape rules. Multi-word quoted passwords (4+ words) look like sentences and are skipped unless the key is `passphrase`/`seed`/`mnemonic`.
- **Names:** only with a cue, an email that contains the name, a name found elsewhere in the same text, or a custom list. Uncued names (“yesterday Fatima Hussain called”) are only found in Aggressive mode, and only if both parts are in the generated lists. Unknown first names after a greeting (“Hi Oluwaseun,”) are missed. Organizations need a legal suffix. Postal addresses are not covered.
- The metrics come from a corpus I wrote myself (38 fixtures, 291 labelled spans, 12 of them held out); real-world accuracy will be lower. Read the masked text before you paste it.
- Numeric placeholders (a PIN stored as a JSON number) are unique within an input; restore matches the bare digits, so an unrelated identical number in the AI's reply could be restored by mistake.
- Pasted text has no file name, so its type is recognised from the content: env, properties, INI/TOML, YAML, JSON, JSON Lines, XML/HTML, CSV, Markdown, logs, mails and diffs, and the ten code languages. On real files from `node_modules` read without their names: JSON 79/79, TypeScript 118/118, shell 10/10, HTML 6/6, Markdown 73/76, JavaScript 190/205 (the misses are minified bundles). A sniffed YAML/JSON/XML document that does not parse is treated as text. A wrong guess can still hide cue-less secrets; a file name or a code fence removes the guess.
- Chatbots may rewrite or drop placeholders. Restore accepts the usual changes (no brackets, backticks, other case, `-` or a space for `_`, markdown escapes such as `\[PASSWORD\_1\]`), and the report lists what did not come back and what the AI invented.
- Files: UTF-8, UTF-16 with BOM (Windows PowerShell output) and, when a file is not valid UTF-8, the Windows code page of the browser language; text files up to 25 MB, images and documents up to 100 MB. No encrypted mapping file yet.
- **Images:** OCR misreads characters, so a value can be missed or restored with a wrong character (correct it in the review). Measured on the corpus rendered as screenshots (`npm run metrics:media`, spans counted when ≥ 98% covered): clean screenshots 94.8% of 291 labelled spans, monospace code font 89.7% (OCR misreads more there), dark mode 94.5%, small text (12 px) 92.8%, photo-like (JPEG quality 60, rotated 1°, serif) 88.0%; about 3 s per image. Every value still readable in a redacted copy was one that detection missed: nothing that was masked could be read again. Misses are mostly names, tables whose header row the OCR damaged, and dates and MAC addresses in small or photographed text. Handwriting, signatures, faces, logos, stylised or tiny text (under about 10 px), non-Latin scripts and what a photo shows (a place, a screen in the background) are not found: review stays necessary.
- **PDF:** measured with the corpus printed to PDF (`npm run metrics:media -- --pdf`): text PDFs 99.3% (Arial) and 98.3% (monospace) of 291 labelled values masked everywhere they occur in the document text, about 1.5 s per page including the OCR check of the copy; scanned PDFs (a screenshot as the page) 91.8% of spans covered, about 3.3 s per page. Every value still readable in a copy was a detection miss (names without cues, organisation names split by a line break inside a word, a CSV whose header the OCR damaged); nothing that was masked could be read. The copy is made of images: its text cannot be selected or searched, it is larger than the original, and digital signatures are gone. Character positions inside a run of text are estimated, so a box can be slightly too wide (the OCR check covers what still shows). Text drawn as shapes on a page that also has normal text is only read with *OCR on every page*. CJK text (no character maps bundled) and XFA forms are not supported. Pages over the limit are left out of the copy and the text.
- **Office:** measured with the corpus written as Office files, values split across formatting runs (`npm run metrics:office`, runs in Node): Word 99.3% and PowerPoint 96.2% of 291 labelled values masked wherever they occur; Excel 18 of 18 for CSV fixtures as sheets (91.1% when code and chat fixtures are forced into one line per cell); every copy is well-formed XML and LibreOffice opens all 108. Old binary files (.doc, .xls, .ppt) and password-protected files are not read: save them as .docx, .xlsx or .pptx without a password. Sheet names are not masked (Excel forbids the brackets of placeholders there). A masked number becomes text, so calculations that use it stop working; formulas without masked results keep their text. Hidden text, rows and sheets are masked like visible ones and stay hidden. EMF/WMF pictures and OLE objects are blanked, not checked.

## Privacy design
- No backend, no external APIs, CDNs, web fonts, analytics or telemetry. Every dependency is bundled.
- A strict Content-Security-Policy (`default-src 'none'`, `connect-src 'none'`, script and style allowed by hash, workers from `blob:` only) makes the browser refuse any request to another origin. `npm run build` fails if the file contains an external URL, a network primitive or a weaker policy, and `npm run smoke` proves in Chromium that `fetch` is blocked.
- `airlock-media.html` allows one thing more: WebAssembly compilation (`'wasm-unsafe-eval'`, JavaScript `eval` stays blocked). The OCR engine, its language data, the PDF reader and the face model are embedded in the file as inert data blocks and handed to workers in memory; `connect-src 'none'` applies inside the workers too, and the smoke test checks that no request is made while it redacts images and PDFs.
- Detection runs in an inline Web Worker. Original values and the mapping live in memory only; the tab warns before closing while a mapping exists and *Forget everything* wipes it. Only settings, profiles and always-mask lists are stored (localStorage, unencrypted). Stored settings and imported profiles are checked field by field, so a damaged file cannot break detection.

## Configuration
The review panel works with the mouse and the keyboard (Tab to a highlight, Enter for details). Settings → global sensitivity (Strict: validated/known formats only; Balanced: adds context rules; Aggressive: adds entropy and heuristics), on/off, sensitivity, scopes (prose, comment, string, config, identifier, key) and placeholder style (token, format-preserving fake, irreversible █████) per category and per detector; cue-word and qualifier lists; allowlist (terms and regexes); lists and regex rules; IP/host/ID-pack options. Profiles (built-in presets *Source code*, *Config and logs*, *Business text / email*, plus your own) export and import as JSON so a security team can share one standard profile.

## Develop
```
npm ci
npm test          # unit tests + corpus (structure guard + byte-identical round trip on every fixture)
npm run metrics   # precision / recall per category, detector and type  (-- --details --set=dev|holdout --strict --sniff)
npm run metrics:media   # the corpus as screenshots in 5 styles through airlock-media.html (needs the build; -- --quick --details); -- --pdf: as text and scanned PDFs
npm run metrics:office  # the corpus as DOCX, PPTX and XLSX through the Office pipeline in Node (-- --details --kind=docx --soffice)
npm run build     # typecheck + dist/airlock.html + dist/airlock-media.html (images, PDF, Office) + offline/CSP checks
npm run smoke     # opens both files from file:// in Chromium (needs the build)
```
The name lists are generated from `@faker-js/faker` (MIT) by `scripts/gen-names.ts` (run by the npm `pre*` hooks). `.github/workflows/pages.yml` builds and publishes the file to GitHub Pages (`docs/deploy.yml` is a copy in case workflow files cannot be pushed). See `CLAUDE.md` for the architecture.

### Add a detector
1. Create `src/engine/detectors/<name>.ts` exporting a `Detector` (`id`, `category`, `types`, `defaultScopes`, `detect(doc, cfg, ctx) → Hit[]`; linear time, no catastrophic regexes). Use `doc.segments`/`doc.pairs` for structure, `mkHit` for hits, `SENS_RANK[cfg.sensitivity]` to gate rules by sensitivity.
2. Add it to `BASE_DETECTORS` in `src/engine/index.ts` and to `DETECTOR_META` in `src/engine/meta.ts` (a test keeps them in sync). New placeholder types go in `CAT_OF_TYPE` (`detectors/helpers.ts`) and `KNOWN_TYPES` (`restore.ts`).
3. Add labelled fixtures (`tests/corpus/*.fixture`, `⟦TYPE:text⟧` marks expected spans; use `{{macro}}` generators from `tests/tokens.ts` for anything token-shaped) and run `npm run metrics -- --details`.

### Add an ID pack
Create `src/engine/detectors/ids/<country>.ts` (or add to `packs.ts`) exporting an `IdPack` (`id`, `type`, a global `re`, optional `cue`, and `validate(match, cue)` returning a confidence or `null`), append it to `ID_PACKS` in `ids/index.ts`, and add `{ id, label }` to `ID_PACK_META` in `meta.ts` (and the id to `ID_PACK_IDS` in `settings.ts`). Add the placeholder type to `CAT_OF_TYPE` and `KNOWN_TYPES`. Users can switch each pack off in Settings.
